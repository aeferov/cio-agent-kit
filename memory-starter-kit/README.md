# memory-starter-kit — память агента между сессиями

Минимальный набор, чтобы новая сессия начиналась не с чистого листа. Три файла-шаблона
и один хук: всё, что нужно, чтобы агент помнил вчерашний день и замечал изменения,
случившиеся без него.

Это не готовая система, а каркас на вечер работы. Дальше он обрастает под ваши привычки.

## Как это работает

**Каталог памяти на проект.** Обычные markdown-файлы, по одному факту в файле.
Индекс подгружается в каждую сессию целиком, остальное агент дочитывает по надобности.

**Записка следующей сессии.** В конце работы агент пишет, что сделано и почему, какие
хвосты остались. В шапке записки — хеш коммита на момент записи.

**Сверка при старте.** Хук поднимает последнюю записку и сравнивает её хеш с текущим
состоянием репозитория. Разошлось — печатает дельту: значит, между сессиями кто-то
коммитил, и это надо прочитать до начала работы. Без сверки агент уверенно работает
по картине, которой уже нет.

**Дословный реестр требований.** Отдельный файл, потому что пересказ съедает формулировки:
«всегда делай так», сказанное один раз, в сводку не попадёт.

## Установка

```bash
cp session-start.sh ~/.claude/hooks/
chmod +x ~/.claude/hooks/session-start.sh
```

В `~/.claude/settings.json`:

```json
{
  "hooks": {
    "SessionStart": [
      { "hooks": [ { "type": "command", "command": "bash $HOME/.claude/hooks/session-start.sh" } ] }
    ]
  }
}
```

Дальше в проекте создать каталог памяти и положить туда шаблоны:

```bash
SLUG=$(pwd -P | sed 's/[^A-Za-z0-9]/-/g')
mkdir -p ~/.claude/projects/$SLUG/memory
cp templates/index.md ~/.claude/projects/$SLUG/memory/
cp templates/requirements-ledger.md ~/.claude/projects/$SLUG/memory/
```

Записку в конце работы агент пишет по `templates/handoff.md` — попросите его словами
«сохрани состояние сессии» и укажите на шаблон.

## Проверка, что работает

Хук молчит, если памяти нет. Если записка есть — печатает её суть, а при расхождении
хеша показывает список коммитов, появившихся с прошлого раза.

## Что дальше

Каркас закрывает главное. Дальше по мере надобности добавляются: журнал сессий с отметкой
покрытия (ловит сессии, оборвавшиеся без записки), автопуш памяти в отдельный репозиторий,
семантический поиск по всем проектам сразу. Это уже надстройки — начинать с них не нужно.

## Оговорки

Скрипт читает файлы памяти и вызывает `git log` в текущем репозитории. Наружу ничего
не отправляет, ничего не пишет, сам не обновляется.

⚠ Всё, что попадает в `hooks`, ваш агент выполняет автоматически. Прочитайте код перед
установкой — это относится к любому чужому хуку, не только к этому.

Слаг каталога памяти считается из **абсолютного пути** проекта. Один и тот же проект
на двух машинах с разными путями получит две разные памяти — если работаете с двух мест,
сводите каталог симлинком, иначе половина записей будет теряться незаметно.
