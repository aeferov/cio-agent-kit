# Память агента между сессиями

Контекст модели конечен. Новая сессия стартует с нуля, и вчерашние решения для неё
не существуют. Встроенная память чат-сервисов хранит факты о вас, а не решения по
проектам: «предпочитает Python» она запомнит, «почему в июле отказались от очереди
на Redis» забудет.

Здесь минимальный набор, который эту дыру закрывает: 3 шаблона и 2 хука, примерно
100 строк кода. Работает на **Claude Code**, идея переносима на любой агент с хуками
на начало и конец сессии.

Парный пост: **[@bender_CIO](https://t.me/bender_CIO)** — там объяснено, зачем это
всё, на живых примерах.

## Из чего состоит

```
templates/
  MEMORY.md                        индекс заметок — грузится в каждую сессию
  project_handoff_YYYY_MM_DD.md    заметка-передача: что сделано и почему
  requirements-ledger.md           дословные требования со статусами
hooks/
  session-start.sh                 подсовывает передачу + сверяет HEAD
  session-end.sh                   маркер штатного завершения
```

## Как это работает

**Каталог памяти на проект.** Обычные markdown-файлы. Одна заметка равна одному
факту, решению или открытому вопросу. Индекс `MEMORY.md` подгружается целиком каждую
сессию, остальное агент дочитывает по надобности. На 40 заметках индекс весит около
4 КБ, а весь каталог — 200 КБ: разница в 50 раз и есть причина, по которой они
разделены.

**Заметка-передача в конце работы.** Что сделано и ПОЧЕМУ, ключевые решения, открытые
хвосты. В шапке два служебных поля: идентификатор сессии и **хеш коммита, на котором
остановились**.

**Сверка на старте.** Хук вбрасывает последнюю передачу в контекст и сравнивает хеш
из шапки с текущим `HEAD`. Если они разошлись, между сессиями были чужие коммиты: другая
машина, параллельная сессия, коллега. Тогда агент читает дельту прежде, чем работать по
устаревшей картине.

Это не теория. Без сверки агент регулярно предлагает сделать то, что уже сделано вчера
в соседнем окне.

**Маркер завершения.** Событие конца сессии не срабатывает при крахе или перезагрузке.
Значит, свежий транскрипт без маркера означает оборванную сессию, чью работу никто не
записал. Хук на старте их считает и предупреждает числом.

## Установка

1. Положите `hooks/` куда удобно, например `~/.claude/hooks/`, и сделайте исполняемыми:
   ```bash
   chmod +x ~/.claude/hooks/session-*.sh
   ```
2. Пропишите в `~/.claude/settings.json`:
   ```json
   {
     "hooks": {
       "SessionStart": [{"hooks": [{"type": "command", "command": "bash $HOME/.claude/hooks/session-start.sh"}]}],
       "SessionEnd":   [{"hooks": [{"type": "command", "command": "bash $HOME/.claude/hooks/session-end.sh"}]}]
     }
   }
   ```
3. Заведите каталог памяти проекта и положите туда `MEMORY.md` из шаблонов.
   Имя каталога агент собирает из абсолютного пути проекта, заменяя каждый
   не-алфанумерик дефисом. Проект `/home/user/projects/shop` даст
   `~/.claude/projects/-home-user-projects-shop/memory/`. Корень переопределяется
   переменной `AGENT_MEMORY_ROOT`.

Проверить, что хук работает: `cd` в проект и `bash ~/.claude/hooks/session-start.sh` —
должен напечатать индекс памяти.

## Грабли, за которые заплачено

**Имя каталога памяти собрано из абсолютного пути проекта.** Отсюда две ловушки.
Первая: путь различается на разных машинах, `/Users/…` против `/home/…`, и один проект
тихо живёт под двумя каталогами памяти. Каждая сессия читает свою половину как полную,
и заметить это неоткуда. Лечится симлинком, а не дисциплиной. Вторая ловушка: проект
переименовали, а память осталась под старым именем.

**Заметка-передача пишется в конце, но сессия может оборваться раньше.** Тогда работа
после последней записи теряется. Поэтому нужен и маркер завершения, и учёт: какие
сессии сдали дела, а какие нет.

**Пересказ теряет дословные просьбы.** Сводка съедает именно ту формулировку, ради
которой всё заводилось. Поэтому реестр требований хранит цитаты, а не пересказ.

**Память есть снимок прошлого, а не истина.** Прежде чем утверждать по заметке,
сверьтесь с кодом. Путь, флаг или число могли измениться за месяц. Заметка, ссылающаяся
на исчезнувший файл, вреднее её отсутствия.

## Чего здесь нет

Восстановления оборванных сессий из транскрипта, федеративного поиска по всем
проектам, учёта покрытия. Это надстройки — они имеют смысл, когда базовый слой уже
прижился и стало ясно, чего не хватает именно вам.
